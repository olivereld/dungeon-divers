# Fase 9 — Compleción Estructural de Dungeon: Puertas, Escaleras y Multi-Floor

## Objetivo

Transformar la dungeon actual en una unidad espacial completa:

```text
Dungeon
│
├── Floor 1
│   ├── Rooms
│   ├── Corridors
│   ├── Walls
│   ├── Doors
│   ├── Start / Objectives
│   └── Stair Down
│
├── Floor 2
│   ├── Rooms
│   ├── Corridors
│   ├── Walls
│   ├── Doors
│   ├── Objectives
│   └── Stair Up / Down
│
└── Floor N
    ├── Rooms
    ├── Corridors
    ├── Walls
    ├── Doors
    └── Stair Up / Exit
```

Sin enemigos, IA, controlador del jugador, combate, inventario runtime ni gameplay runtime.

Eso queda fuera.

## 2.1 Las puertas físicas ya existen

# 8. Problema que debemos resolver con las puertas + paredes

Aquí está probablemente uno de los puntos más importantes de esta fase.

Si generamos una pared continua a partir del `CellGrid`:

```text
████████████████
████      ██████
████      ██████
████████████████
```

y existe una puerta:

```text
██████╔══╗██████
██████║  ║██████
██████╚══╝██████
```

la pared continua **no puede cerrar el vano de la puerta**.

Por tanto necesitamos que:

```text
WallMeshGenerator
```

conozca una máscara de exclusión estructural:

```text
door openings
```

pero **sin conocer DoorPair directamente**.

La solución correcta sería introducir un contrato geométrico neutral:

```text
WallOpening
```

por ejemplo:

```text
WallOpening
    position
    side
    width
    height
    connection_id
```

Entonces:

```text
DoorPair
   ↓
DoorOpeningManifest
   ↓
WallMeshGenerator
```

Esto es mucho mejor que hacer que el generador de paredes conozca la semántica de puertas.

### Dungeon de un piso

* [ ] Cada conexión estructural tiene sus `DoorPair`.
* [ ] Cada `DoorPair` tiene dos `DoorPlacement` válidos.
* [ ] Las puertas se materializan exactamente donde indica `DoorPair`.
* [ ] La orientación procede exclusivamente de `DoorPlacement.side`.
* [ ] El wall mesh respeta los vanos de puerta.
* [ ] No existen solapamientos puerta/pared.
* [ ] No se modifican `CellGrid`, `Rooms` ni `DungeonSemanticResult`.

### Multi-floor

* [ ] Existe `StairData`.
* [ ] Existe `FloorConnection`.
* [ ] Existe `DungeonFloorData`.
* [ ] Existe `DungeonMultiFloorResult`.
* [ ] Se pueden generar N pisos.
* [ ] Cada piso tiene seed determinista.
* [ ] Los pisos están conectados mediante escaleras.
* [ ] No existen pisos aislados.
* [ ] Las escaleras ocupan celdas transitables.
* [ ] Las conexiones verticales son verificadas.

### Presentación

* [ ] Las paredes continuas se generan correctamente.
* [ ] Los vanos de puertas son geométricamente reales.
* [ ] Las puertas se instancian.
* [ ] Las escaleras se instancian.
* [ ] El staging sigue siendo atómico.
* [ ] Una presentación válida nunca es reemplazada por una inválida.

### Arquitectura

* [ ] Cero Player Controller.
* [ ] Cero Enemy AI.
* [ ] Cero Boss AI.
* [ ] Cero combate.
* [ ] Cero inventario runtime.
